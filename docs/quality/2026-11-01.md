# Quality check against the 10 rules (2026-11-01)

Checked on 2026-11-14, when M1 was built, on Windows 11 with Python 3.14.5 and Node.js 24.19.0.
The code is a JavaScript tracker (`js/src`), a Python collector with SQLite storage
(`python/src/event_tracking_pipeline`) and an end-to-end script (`scripts/e2e.py`).

## Rules

| # | Rule | Status | Evidence |
|---|---|---|---|
| 1 | Assume every call can fail | pass | Tracker: `fetchTransport` aborts after `timeoutMs` (10 s, `AbortSignal.timeout`); failures are retried with capped, jittered backoff and a per-event limit (`maxAttempts`), drops are reported via `onError` (`tracker.test.js`: retry, exhaustion, 4xx tests). Storage errors in `queue.js` are reported, not swallowed. Collector: socket timeout 10 s (`server.py`), SQLite `timeout=5.0`; a `sqlite3.Error` is logged and answered with 503 so the client retries (`test_store_failure_answers_503_so_clients_retry`). `scripts/e2e.py` runs node with a 60 s timeout. ruff `BLE`, `S110`, `E722` are enabled and clean. |
| 2 | Writes safe to retry | pass | `events.event_id` primary key with `INSERT OR IGNORE`; dead letters keyed by SHA-256 of reason and payload with an upsert of `seen`. One transaction per batch, rolled back on error. Tests: `test_writing_the_same_batch_twice_stores_it_once`, `test_retried_batch_is_counted_as_duplicates`, `test_failed_batch_writes_nothing`; e2e replay gives `accepted 0, duplicates 10`. The tracker keeps the same `event_id` on every retry. |
| 3 | No race conditions | pass | Collector: one lock around every SQLite use; `test_concurrent_writers_store_each_event_exactly_once` (8 threads) and `test_concurrent_clients_with_overlapping_retries` (6 HTTP clients). Tracker: one drain at a time (`concurrent flush calls share one drain`); delivered events are removed by id, so consent changes, overflow or new events during an in-flight send cannot remove the wrong events (two tests; mutant J3 below). |
| 4 | Don't trust the clock | pass | No durations are computed from wall-clock time; the e2e deadline uses `performance.now()`. Stored times are UTC: `received_at` from `datetime.now(UTC)`, client `timestamp` must end in `Z` and be a real date. Events are not ordered by time in M1; the client time is stored next to the server time (skew correction is an M2 item, RFC risks). |
| 5 | Read before changing | pass | Env vars read: `ETP_DB`, `ETP_HOST`, `ETP_PORT`, `ETP_ALLOWED_ORIGINS` (`cli.py`), all documented in the README and tested in `test_environment_defaults`. APIs used exist in the installed versions (`String.prototype.isWellFormed` and `AbortSignal.timeout` in Node 24, `datetime.UTC` in Python 3.11+, `Draft202012Validator` in jsonschema 4.26). README links checked by `audit_repo.py`. |
| 6 | Never break compatibility | pass | New repository. The schema is versioned (`schema_version` const 1, file `event.v1.json`); CONTRIBUTING and the RFC say new fields are optional and anything else is a new version. |
| 7 | One source of truth | pass | One schema file, used by the collector, the CLI `validate` command and the tests; no pydantic models duplicate it (ADR 0002). The tracker's name and property checks mirror the schema's limits and are covered by the e2e run, where the collector validates real tracker output. Version 0.1.0 agrees in `pyproject.toml`, `__init__.py`, `package.json` and `LIBRARY` in `tracker.js`; Python 3.11+ (CI 3.12) and Node.js 24 agree in README, CI and manifests. |
| 8 | Small changes, no secrets, validate input | pass | No secrets or keys (no third-party SDKs, no real endpoints; test hosts use `.test` and loopback). Input limits: body 256 KB (413), 100 events per batch, `Content-Length` required, NaN/Infinity and nesting depth errors dead-lettered, dead-letter payload capped at 16 KB, untrusted text in problem messages JSON-quoted and capped (64 characters per value, 5 keys listed) and escaped again before the CLI prints it (`text.py`, `test_escaping.py`), CLI ports, origins and file sizes checked. Tracker: names, properties, user ids, event size (32 KB) and every option validated. |
| 9 | Tests that can actually fail | pass | No skipped or assertion-free tests; the only `skipif` is the e2e test when `node` is missing (reason given). Error and empty paths are covered for each entry point (`ingest`, WSGI routes, CLI, `createTracker`, queue, transport). 23 hand mutations below: 21 killed, 2 equivalent. Three real defects were found while writing and reviewing tests (results doc: lone surrogates crashed the insert; the identify rule fired without a `type`; unescaped envelope keys and report output allowed terminal escape injection). |
| 10 | Re-verify | pass | `.tmp/check.sh` twice: ruff `All checks passed!`; mypy `Success: no issues found in 17 source files`; pytest `136 passed`; node `pass 64`, `fail 0`; `E2E PASS`; pip-audit `No known vulnerabilities found`; npm audit `found 0 vulnerabilities`; `CHECK PASS`. `audit_repo.py event-tracking-pipeline`: OK. CI has not run yet (not pushed). |
