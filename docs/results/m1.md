# M1 results

Measured on 2026-11-14 on Windows 11, Intel Core i7-13700H, 13.7 GB RAM, with Python 3.14.5
(jsonschema 4.26.0, pytest 9.2.0, ruff 0.17.5, mypy 2.4.1) and Node.js 24.19.0 (npm 11.17.0).
CI (Python 3.12, Node.js 24 on ubuntu-latest) has not run yet: the repository is not pushed.

`make` is not installed on this machine, so the Makefile's commands were run directly through
`.tmp/check.sh` (not committed):

```bash

cd js && npm run lint && npm test
```

## Analyze

- The collector's books balance: every event the e2e run sent is either in `events` (201) or in
  `dead_letters` (3 schema + 1 body); replaying a batch adds nothing.
- The tracker lost nothing across an offline start and a network drop; the 21st request is the one
  retry.
- Defects found while building and reviewing M1 (all fixed, with tests):
  1. An event whose strings held a lone surrogate (JSON escape `\ud800`) passed the schema and then
     crashed the SQLite insert with `UnicodeEncodeError`, which is not a `sqlite3.Error`, so the
     request would have failed with HTTP 500 instead of being dead-lettered. The validator now
     rejects such events, dead-letter text is stored with backslash escapes, and the tracker refuses
     non-well-formed strings (`isWellFormed`).
  2. The schema's "identify needs user_id" rule fired on events with no `type` at all (an `if`
     without `required` matches vacuously), giving a misleading second error. The `if` now requires
     `type`.
  3. Terminal escape injection (found in a security review): unknown envelope keys sent by a
     client went into the 400 message and the dead-letter detail as they were, and
     `etp-collector report` printed stored details without escaping, so a client could put ANSI
     escape sequences or fake lines into an operator's terminal. Now every untrusted value in a
     problem message is JSON-quoted and capped at 64 characters, at most 5 keys are listed (then
     "and N more"), JSON pointer parts are escaped, and the CLI escapes every non-printable
     character before printing (`text.py`).

## Improve and Control

- Improvements are the three fixes above; each has a test that fails without it.
- Control: `make lint` (ruff, mypy --strict, node --check), `make test`, the e2e step and the audit
  run in CI on every push; the e2e step prints its result as a `::notice` (or `::error`). The schema
  is one file used by the collector, the CLI and the tests.
- 23 hand mutations: 21 killed, 2 shown equivalent; see
  [docs/quality/2026-11-01.md](../quality/2026-11-01.md).
